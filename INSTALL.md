# Installation

How to build, run, seed, and test the recruiting platform from a clean checkout.

## Prerequisites

Use the Docker instructions to run the built app, or use Node.js for local development. Each npm project has its own lockfile.

| Tool | Version | Needed for |
|---|---|---|
| Node.js | 22.13+ on Node 22, or Node 24 | frontend, backend, tests outside Docker |
| npm | 10 or newer (ships with Node.js) | installing dependencies |
| PostgreSQL | 16 or newer | database (local run without Docker) |
| Docker | 24 or newer | building and running the app and PostgreSQL containers |
| Docker Compose | v2 | optional development database setup |
| Git | any recent | cloning the repo |

Check your versions:

```bash
node -v
npm -v
psql --version
docker --version
```

## 1. Clone

```bash
git clone https://github.com/WilliamJokuS/CSC4801_Team_I_Died_of_a_HeartAttack.git
cd CSC4801_Team_I_Died_of_a_HeartAttack
```

## 2. Environment variables for local development

```bash
cp backend/.env.example backend/.env
node -e 'console.log(require("node:crypto").randomBytes(48).toString("base64url"))'
```

Paste the generated value into `JWT_SECRET` in `backend/.env`. Keep the file local and use database credentials for your development instance.

| Variable | Example | Purpose |
|---|---|---|
| `DATABASE_URL` | `postgres://app:app@localhost:5432/recruiting` | Main database |
| `TEST_DATABASE_URL` | `postgres://app:app@localhost:5432/recruiting_test` | Disposable PostgreSQL database for `npm run test:live` |
| `JWT_SECRET` | Generated by the command above | Signs login tokens and must be at least 32 characters |
| `JWT_EXPIRES_IN` | `24h` | Token lifetime (see `Contract/API_Contract.md`) |
| `PORT` | `8080` | Backend port |
| `AUTH_TRUSTED_PROXIES` | *(optional)* | Comma-separated trusted proxy IPs/CIDRs for Express `trust proxy` |
| `DEMO_SEED_REFERENCE_DATE` | *(optional)* | `YYYY-MM-DD` (UTC) anchor date for deterministic `db:seed` slot timestamps |

## 3. Install dependencies

```bash
npm --prefix backend ci
npm --prefix frontend ci
npm --prefix testing ci
```

## 4. Database setup

The backend uses PostgreSQL through Prisma. From the repository root, start the development database and apply the committed migrations after PostgreSQL is ready.

```bash
docker compose -f backend/docker-compose.dev.yml up -d
until docker compose -f backend/docker-compose.dev.yml exec -T db pg_isready -h 127.0.0.1 -U app -d recruiting; do sleep 1; done
npm --prefix backend run migrate
```

On an existing local PostgreSQL 16+ instance, create `recruiting` with a local login that owns the database, set `DATABASE_URL` in `backend/.env` to match, then run the migration command. Create a separate `recruiting_test` database if you plan to run the live tests.

## 5. Seed demo data

This command resets the configured local database and loads deterministic demo data. For a smoke test, use `alice@demo.test` as a candidate or `hr@acme.demo.test` as an employer. Both demo accounts use `password123`.

```bash
npm --prefix backend run db:seed
```

## 6. Run

```bash
# Backend (terminal 1)
npm --prefix backend run dev

# Frontend (terminal 2)
npm --prefix frontend run dev
```

Then open the URL Vite prints (usually `http://localhost:5173`).

## 7. Run tests

```bash
npm --prefix testing test
```

The unit suite runs non-interactively, exits nonzero on failure, and uses isolated fixtures. See [testing/README.md](testing/README.md) for the separate bug regression and live PostgreSQL suites.

## 8. Docker

Run these commands from the repository root. The app image serves the compiled frontend and API on port 8080. PostgreSQL 16 runs in a second container on a private Docker network. The app container generates a JWT secret and applies migrations on startup.

```bash
docker build -t csc4801-recruiting .
docker pull postgres:16
docker network create csc4801-docker
docker volume create csc4801-docker-data

docker run -d --name csc4801-docker-db \
  --network csc4801-docker --network-alias db \
  -e POSTGRES_USER=app -e POSTGRES_PASSWORD=app -e POSTGRES_DB=recruiting \
  -v csc4801-docker-data:/var/lib/postgresql/data \
  postgres:16

until docker exec csc4801-docker-db pg_isready -h 127.0.0.1 -U app -d recruiting; do sleep 1; done

docker run -d --name csc4801-docker-app --network csc4801-docker \
  -e DATABASE_URL=postgres://app:app@db:5432/recruiting \
  -p 127.0.0.1:8080:8080 csc4801-recruiting
```

After startup, check the API, reset and seed the local demo database, and run the tests inside the app container. The seed command replaces the database contents in one transaction. The image runs migrations on startup.

```bash
curl --retry 15 --retry-connrefused --retry-delay 1 -fsS http://127.0.0.1:8080/api/health
docker exec csc4801-docker-app npm --prefix /app/backend run migrate
docker exec csc4801-docker-app npm --prefix /app/backend run db:seed
docker exec csc4801-docker-app npm --prefix /app/testing test
docker exec csc4801-docker-app npm --prefix /app/testing run test:bugs
```

Run the live PostgreSQL suite against a disposable PostgreSQL instance. The suite modifies the specified test database and uses a role that can create additional temporary databases.

```bash
docker exec csc4801-docker-db createdb -U app recruiting_test
docker exec -e TEST_DATABASE_URL=postgres://app:app@db:5432/recruiting_test \
  csc4801-docker-app npm --prefix /app/testing run test:live
```

Open [the app](http://127.0.0.1:8080), sign in as `alice@demo.test` with `password123`, and open the candidate job list and applications. For the booking demo, sign in as Alice and Bob in separate browser profiles and open their Data Analyst applications. Both see the same future Acme slots. The database persists in `csc4801-docker-data`. Stop and restart the containers with the following commands. An app restart generates a new JWT secret and signs users out.

```bash
docker stop csc4801-docker-app csc4801-docker-db
docker start csc4801-docker-db
until docker exec csc4801-docker-db pg_isready -h 127.0.0.1 -U app -d recruiting; do sleep 1; done
docker start csc4801-docker-app
```

The Docker workflow above documents the current two-container setup. See [the course Docker instructions](reference/DOCKER.md) and [submission requirements](reference/REQUIREMENTS.md#10-submission-protocol) for the graded checkout requirements.

## Before you push: don't upload everything

Only source code and config belong on GitHub. The root `.gitignore` already excludes the following, but always check `git status` before committing, especially in `frontend/`.

**Do NOT commit:**

| Path | Why |
|---|---|
| `node_modules/` | Hundreds of MB; rebuilt by `npm ci` |
| `dist/`, `build/` | Build output; regenerated by `npm run build` |
| `*.tsbuildinfo` | TypeScript cache |
| `coverage/` | Test coverage output |
| `.env`, `.env.local` | Contain secrets; the course forbids real secrets in the repo |
| `.vscode/`, `.idea/`, `.DS_Store` | Personal editor/OS files |

**DO commit (frontend):**

- `frontend/src/`, `frontend/public/`, `frontend/index.html`
- `frontend/package.json` **and** `frontend/package-lock.json`
- Config files: `vite.config.ts`, `tsconfig.json`, `tailwind.config.ts`, `postcss.config.js`

Safe push routine:

```bash
git status                 # look for node_modules, dist, .env: none should appear
git add frontend/          # stage only your own folder
git status                 # check again before committing
git commit -m "..."
git push
```

If you committed something by mistake, untrack it without deleting it locally:

```bash
git rm -r --cached frontend/node_modules
git commit -m "Untrack node_modules"
```

## Troubleshooting

| Problem | Fix |
|---|---|
| `npm ci` fails with a lockfile error | Run `npm install` once, then commit the updated `package-lock.json` |
| `ECONNREFUSED` on port 5432 | PostgreSQL isn't running; start it or use Docker |
| `JWT_SECRET must be at least 32 characters` | Generate a value using the command in section 2 and update `backend/.env` |
| Docker app exits during migrations | Check the app and database with `docker ps -a`. Verify the database is ready, both containers are on `csc4801-docker`, and the Docker `DATABASE_URL` uses the `db` network alias |
| Frontend loads but API calls fail | Check the backend is running and the Vite proxy / `PORT` match |
| Port 8080 already in use | Stop the other process or change the Docker host mapping to `127.0.0.1:8081:8080`. For local development, update `PORT` in `backend/.env` and set `VITE_API_PROXY` to the new backend URL |
