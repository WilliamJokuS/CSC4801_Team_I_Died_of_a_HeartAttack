# Installation

How to build, run, seed, and test the recruiting platform from a clean checkout.

> Status: in development. Steps marked **TODO** will be confirmed once `backend/`, `testing/`, and the `Dockerfile` exist.

## Prerequisites

This is a JavaScript/TypeScript project, so there is no `requirements.txt`. Dependencies are listed in each folder's `package.json` and pinned in `package-lock.json`, and `npm ci` installs them.

| Tool | Version | Needed for |
|---|---|---|
| Node.js | 22 LTS or newer | frontend, backend, tests |
| npm | 10 or newer (ships with Node.js) | installing dependencies |
| PostgreSQL | 16 or newer | database (local run without Docker) |
| Docker | 24 or newer | building and running the full environment |
| Git | any recent | cloning the repo |

Check your versions:

```bash
node -v
npm -v
psql --version
docker --version
```

## 1. Clone

```bash
git clone https://github.com/WilliamJokuS/CSC4801.git
cd CSC4801
```

## 2. Environment variables

```bash
cp .env.example .env
```

Edit `.env` with your local values. Never commit `.env`.

| Variable | Example | Purpose |
|---|---|---|
| `DATABASE_URL` | `postgres://app:app@localhost:5432/recruiting` | Main database |
| `TEST_DATABASE_URL` | `postgres://app:app@localhost:5432/recruiting_test` | Isolated test database |
| `JWT_SECRET` | `change-me` | Signs login tokens |
| `JWT_EXPIRES_IN` | `24h` | Token lifetime (see `Contract/API_Contract.md`) |
| `PORT` | `8080` | Backend port |

**TODO:** confirm the final list once the backend is written, and keep `.env.example` in sync.

## 3. Install dependencies

```bash
cd frontend && npm ci && cd ..
cd backend  && npm ci && cd ..
cd testing  && npm ci && cd ..
```

## 4. Database setup

Engine: **PostgreSQL**, accessed through the **Prisma** ORM (`backend/prisma/schema.prisma`).

```bash
createdb recruiting
createdb recruiting_test
cd backend
npx prisma migrate deploy   # applies committed migrations (use `migrate dev` while developing new ones)
```

## 5. Seed demo data

Resets the local database and loads the demo accounts listed in `README.md`.

```bash
cd backend && npx prisma db seed
```

## 6. Run

```bash
# Backend (terminal 1)
cd backend && npm run dev

# Frontend (terminal 2)
cd frontend && npm run dev
```

Then open the URL Vite prints (usually `http://localhost:5173`).

## Before you push: don't upload everything

Only source code and config belong on GitHub. The root `.gitignore` already excludes the following, but always check `git status` before committing, especially in `frontend/`.

**Do NOT commit:**

| Path | Why |
|---|---|
| `node_modules/` | Hundreds of MB; rebuilt by `npm ci` |
| `dist/`, `build/` | Build output; regenerated by `npm run build` |
| `*.tsbuildinfo` | TypeScript cache |
| `coverage/` | Test coverage output |
| `.env`, `.env.local` | Contain secrets; the course forbids real secrets in the repo |
| `.vscode/`, `.idea/`, `.DS_Store` | Personal editor/OS files |

**DO commit (frontend):**

- `frontend/src/`, `frontend/public/`, `frontend/index.html`
- `frontend/package.json` **and** `frontend/package-lock.json`
- Config files: `vite.config.ts`, `tsconfig.json`, `tailwind.config.ts`, `postcss.config.js`

Safe push routine:

```bash
git status                 # look for node_modules, dist, .env: none should appear
git add frontend/          # stage only your own folder
git status                 # check again before committing
git commit -m "..."
git push
```

If you committed something by mistake, untrack it without deleting it locally:

```bash
git rm -r --cached frontend/node_modules
git commit -m "Untrack node_modules"
```

## Troubleshooting

| Problem | Fix |
|---|---|
| `npm ci` fails with a lockfile error | Run `npm install` once, then commit the updated `package-lock.json` |
| `ECONNREFUSED` on port 5432 | PostgreSQL isn't running; start it or use Docker |
| Frontend loads but API calls fail | Check the backend is running and the Vite proxy / `PORT` match |
| Port already in use | Stop the other process or change `PORT` in `.env` |
